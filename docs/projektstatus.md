## Introducerade begrepp
| Begrepp | Kapitel | Kort definition |
|---|---|---|
| Enterprise arkitektur som förmåga | 1 | Arkitekturarbete som samlad organisatorisk förmåga, inte enbart central leverans. |
| Central utvecklingsfunktion | 1 | Funktion som stödjer, samordnar och kvalitetssäkrar helheten. |
| Utvecklingsområde | 1 | Del av organisationen som äger behov och arkitekturarbete nära verksamheten. |
| Faslogik | 2 | Arbetssätt där utveckling delas upp i tydliga steg med beslutspunkter mellan stegen. |
| Kontinuerlig utvecklingslogik | 2 | Arbetssätt där behov, lösningar, prioriteringar och lärande hanteras löpande. |
| Arkitekturellt lärande | 2 | Kunskap som byggs upp när organisationen prövar lösningar, upptäcker konsekvenser och justerar riktning. |
| Beslutskapacitet | 2 | Förmågan att fatta tillräckligt bra arkitekturbeslut löpande där besluten uppstår. |
| Riktningsskapande | 3 | Att formulera, förankra och vidareutveckla gemensam riktning som lokala beslut kan använda. |
| Aktiverande stöd | 3 | Stöd som stärker utvecklingsområdenas egen arkitekturförmåga i stället för att skapa beroende. |
| Helhetskvalitet | 3 | Kvaliteten i hur organisationens samlade utveckling hänger ihop över tid. |
| Lokalt arkitekturägarskap | 4 | Utvecklingsområdets ansvar att förstå, forma och följa upp arkitekturen inom sitt område. |
| Områdesarkitektur | 4 | Sammanhållen bild av verksamhet, information, lösningar, beroenden och vägval inom ett utvecklingsområde. |
| Arkitekturell konsekvensbedömning | 4 | Lättviktig bedömning av hur ett behov eller initiativ påverkar struktur, beroenden, kvalitet och gemensam riktning. |
| Gemensam riktning | 5 | Sammanhållen riktning som hjälper lokala beslut att stödja helheten. |
| Arkitekturprincip | 5 | Vägledande regel som hjälper organisationen att fatta konsekventa arkitekturbeslut. |
| Målarkitektur | 5 | Målbild för hur viktiga delar av helheten bör utvecklas över tid. |
| Guardrail | 5 | Tydlig ram som ger handlingsfrihet inom accepterade gränser. |
| Bindande riktning | 5 | Riktning som ska följas eftersom avsteg kan skapa stor risk eller kostnad. |
| Vägledande riktning | 5 | Riktning som bör följas men där lokal variation kan accepteras med motivering. |
| Utforskande riktning | 5 | Preliminär riktning som används för lärande innan ett vägval låses. |

| Arkitekturforum | 6 | Återkommande samverkansyta där arkitekturella frågor diskuteras, bedöms och ibland beslutas. |
| Beslutsmandat | 6 | Tydlighet om vem som får fatta vilket beslut och på vilken grund. |
| Beslutslogg | 6 | Lättviktigt minne över viktiga vägval, motiveringar och eventuella villkor. |

| Arkitekturell triagering | 7 | Snabb sortering av vilken arkitekturell hantering ett behov eller initiativ behöver. |
| Påverkningsnivå | 7 | Bedömning av om påverkan är lokal, beroendehanterad, gemensam eller strategisk. |
| Behovsflöde | 7 | Vägen från identifierat behov till initiativ, påverkanbedömning, beslut och uppföljning. |

| Beroendekarta | 8 | Lättviktigt arbetsredskap för att synliggöra beroenden mellan utvecklingsområden. |
| Informationsberoende | 8 | Beroende där information, begrepp eller datakvalitet från ett område påverkar ett annat. |
| Lösningsberoende | 8 | Beroende där system, tjänster, integrationer eller tekniska vägval påverkar andra områden. |
| Beslutsberoende | 8 | Beroende där ett beslut behöver samordnas eller fattas gemensamt på grund av bredare påverkan. |

| Gemensam förmåga | 9 | Något organisationen behöver kunna göra sammanhållet över flera utvecklingsområden. |
| Gemensam plattform | 9 | En teknisk eller organisatorisk grund som flera utvecklingsområden kan bygga vidare på. |
| Standard | 9 | En överenskommelse om hur något ska beskrivas, utformas, integreras, dokumenteras eller följas upp. |
| Gemensamhetsgrad | 9 | Bedömning av hur starkt en lösning, förmåga eller standard bör vara gemensam respektive lokal. |

| Gemensamt minne | 10 | Den samlade arkitekturdokumentation som hjälper organisationen att förstå riktning, beslut, beroenden och lärdomar över tid. |
| Minsta användbara dokumentation | 10 | Den minsta dokumentation som räcker för nästa beslut, nästa samordning och nästa lärande. |
| Dokumentationskarta | 10 | Översikt över dokumentationstyper, ägare, placering och uppdateringstillfällen. |
| Dokumentationslivscykel | 10 | Status och hantering för dokumentation över tid, exempelvis utkast, gällande, under omprövning, ersatt och arkiverat. |

| Arkitekturell kvalitet | 11 | Hur väl arkitekturarbetet stödjer långsiktig verksamhetsnytta, sammanhang och förändringsförmåga. |
| Kontrollmått | 11 | Mått som visar om en aktivitet eller leverans har genomförts. |
| Lärandemått | 11 | Mått eller signal som hjälper organisationen att förstå och förbättra arbetssättet. |
| Kvalitetsdialog | 11 | Återkommande samtal där signaler, avsteg och mönster tolkas för att driva förbättring. |

| Hållbar decentraliserad arkitekturförmåga | 12 | Organisationens förmåga att förena lokalt arkitekturägarskap med gemensam riktning, lärande och helhetskvalitet över tid. |
| Autonomi med sammanhang | 12 | En balans där utvecklingsområden har handlingsfrihet inom tydliga ramar som skyddar helheten. |
| Förmågebyggare | 12 | Roll där den centrala funktionen stärker organisationens egen förmåga att fatta och följa upp arkitekturbeslut. |
