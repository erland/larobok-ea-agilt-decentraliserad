# Terminologi

| Begrepp | Definition i boken |
|---|---|
| Enterprise arkitektur | Förmågan att skapa gemensam riktning, sammanhang och kvalitet i hur verksamhet, information, system och teknik utvecklas över tid. |
| Decentraliserad arkitekturorganisation | En organisation där huvuddelen av arkitekturarbetet sker nära utvecklingsområdena, medan central funktion stödjer och håller ihop helheten. |
| Central utvecklingsfunktion | Funktionen som tar initiativ till viktiga helhetsfrågor, stödjer utvecklingsområden och kvalitetssäkrar inriktningen. |
| Utvecklingsområde | En organisatorisk del som ansvarar för att fånga och driva utvecklingsbehov för en del av verksamheten. |
| XLPM-logik | Ett arbetssätt präglat av projekt, faser, beslutspunkter och tidig planering. Begreppet används förenklat som kontrast till kontinuerligt agilt arbete. |
| Agil utvecklingslogik | Ett arbetssätt där behov, prioriteringar, lösningar och lärande utvecklas löpande i kortare cykler. |
| Gemensam riktning | Den sammanhållna målbild, de principer och de avvägningar som hjälper lokala beslut att stödja helheten. |
| Guardrails | Tydliga ramar som ger handlingsfrihet inom accepterade gränser. |
| Faslogik | Ett sätt att organisera utveckling där arbete delas upp i tydliga steg, ofta med beslutspunkter mellan stegen. |
| Kontinuerlig utvecklingslogik | Ett sätt att organisera utveckling där behov, lösningar, prioriteringar och lärande hanteras löpande. |
| Arkitekturellt lärande | Kunskap som organisationen bygger upp när lösningar prövas, konsekvenser upptäcks och riktningen justeras. |
| Beslutskapacitet | Organisationens förmåga att fatta tillräckligt bra beslut löpande, inte bara vid formella beslutspunkter. |

| Riktningsskapande | Att formulera, förankra och vidareutveckla den gemensamma riktning som lokala arkitekturbeslut behöver förhålla sig till. |
| Aktiverande stöd | Stöd som gör utvecklingsområden mer kapabla att själva ta ansvar för arkitekturella avvägningar. |
| Helhetskvalitet | Kvaliteten i hur organisationens samlade utveckling hänger ihop över tid, inte bara kvaliteten i enskilda lösningar. |

| Lokalt arkitekturägarskap | Utvecklingsområdets ansvar att förstå, forma och följa upp arkitekturen inom sitt område. |
| Områdesarkitektur | Den sammanhållna bilden av ett utvecklingsområdes verksamhetsförmågor, information, lösningar, beroenden, vägval och risker. |
| Arkitekturell konsekvensbedömning | En lättviktig bedömning av hur ett behov eller initiativ påverkar struktur, beroenden, kvalitet och gemensam riktning. |
| Arkitekturprincip | En vägledande regel som hjälper organisationen att fatta konsekventa arkitekturbeslut. |
| Målarkitektur | En målbild för hur viktiga delar av verksamhet, information, lösningar eller teknik bör utvecklas över tid. |
| Bindande riktning | Riktning som ska följas eftersom avsteg kan skapa stor risk, kostnad eller svår återställning. |
| Vägledande riktning | Riktning som bör följas men där lokal variation kan accepteras med motivering. |
| Utforskande riktning | Preliminär riktning som används för att pröva och lära innan organisationen låser ett vägval. |


| Arkitekturforum | En återkommande samverkansyta där arkitekturella frågor diskuteras, bedöms och ibland beslutas. |
| Beslutsmandat | Tydlighet om vem som får fatta vilket beslut och på vilken grund. |
| Beslutslogg | Ett enkelt organisatoriskt minne över viktiga vägval, motiveringar, konsekvenser och eventuella villkor. |

| Arkitekturell triagering | En snabb, lättviktig sortering av vilken arkitekturell hantering ett behov eller initiativ behöver. |
| Påverkningsnivå | En bedömning av hur brett eller djupt ett initiativ påverkar arkitektur, beroenden och gemensam riktning. |
| Behovsflöde | Vägen från identifierat behov till initiativ, arkitekturell påverkan, beslut och uppföljning. |


| Beroendekarta | Ett lättviktigt arbetsredskap som visar vilka utvecklingsområden, initiativ och arkitekturella frågor som påverkar varandra. |
| Informationsberoende | Ett beroende där ett område behöver information, begrepp, kvalitet eller tolkning från ett annat område. |
| Lösningsberoende | Ett beroende där ett område påverkas av ett annat områdes system, tjänster, integrationer, plattformar eller tekniska vägval. |
| Beslutsberoende | Ett beroende där ett lokalt beslut behöver samordnas eller avgöras gemensamt eftersom det påverkar flera områden eller helhetsriktningen. |


| Gemensam förmåga | Något organisationen behöver kunna göra sammanhållet över flera utvecklingsområden, till exempel identitetshantering, informationsutbyte eller arkitekturellt beslutsstöd. |
| Gemensam plattform | En teknisk eller organisatorisk grund som flera utvecklingsområden kan bygga vidare på. |
| Standard | En överenskommelse om hur något ska beskrivas, utformas, integreras, dokumenteras eller följas upp. |
| Gemensamhetsgrad | Bedömning av hur starkt en lösning, förmåga eller standard bör vara gemensam respektive lokal. |


| Gemensamt minne | Den samlade arkitekturdokumentation som hjälper organisationen att förstå riktning, beslut, beroenden och lärdomar över tid. |
| Minsta användbara dokumentation | Den minsta dokumentation som räcker för att stödja nästa beslut, nästa samordning och nästa lärande. |
| Dokumentationskarta | En översikt över vilka typer av arkitekturdokumentation som finns, vem som äger dem, var de finns och när de uppdateras. |
| Dokumentationslivscykel | Status och hantering för dokumentation över tid, till exempel utkast, gällande, under omprövning, ersatt och arkiverat. |


| Arkitekturell kvalitet | Hur väl organisationens arkitekturarbete stödjer långsiktig verksamhetsnytta, sammanhang, förändringsförmåga och helhetskvalitet. |
| Kontrollmått | Ett mått som främst visar om en aktivitet, leverans eller kontrollpunkt har genomförts. |
| Lärandemått | Ett mått eller en signal som hjälper organisationen att förstå om arbetssättet leder till bättre beslut, bättre samordning och bättre arkitekturell kvalitet. |
| Kvalitetsdialog | Ett återkommande samtal där centrala och lokala aktörer tolkar signaler, avsteg, beroenden och mönster för att förbättra arkitekturarbetet. |
| Uppföljningsrytm | Den återkommande struktur som anger vad som följs upp lokalt, gemensamt och strategiskt över tid. |

| Hållbar decentraliserad arkitekturförmåga | Organisationens förmåga att förena lokalt arkitekturägarskap med gemensam riktning, lärande och helhetskvalitet över tid. |
| Autonomi med sammanhang | En balans där utvecklingsområden har handlingsfrihet att lösa sina uppgifter inom tydliga ramar som skyddar helheten. |
| Förmågebyggare | En roll där den centrala utvecklingsfunktionen stärker organisationens egen arkitekturförmåga i stället för att bli permanent beslutsnav. |
| Centraliserad tröghet | Riskläge där central funktion äger för mycket och där beslut, stöd eller granskning bromsar lokal utveckling. |
| Lokal splittring | Riskläge där utvecklingsområden arbetar snabbt lokalt men utan tillräcklig gemensam riktning och sammanhang. |
| Symbolisk samordning | Riskläge där forum, principer och dokumentation finns men inte påverkar verkliga beslut. |
